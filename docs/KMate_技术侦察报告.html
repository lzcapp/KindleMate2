◆报告摘要

  • KMate Windows 桌面版 = Python 3.12 + PyInstaller 打包,核心业务 mypyc 编译为原生 .pyd;UI 为 wxPython 外壳 + WebView2 渲染 HTML 视图。
  • 数据极简:一个 SQLite 主库 km3.dat + 两个 JSON 配置 + 缓存/日志骨架;应用视角路径 %LOCALAPPDATA%\KMate\(MSIX 重定向至 Packages 目录)。
  • km3.dat 与旧 KM2.dat / KindleMate2 同源:表名与列名几乎一致,新增 source / note_parent_key / ck_synced / pagenumber 及书目、标签、闪卡状态结构。
  • 行为情报:Windows“云同步”实为把库绑定到云盘路径做文件级同步;微信读书导入 = WebView2 内嵌登录页轮询;词典含自研 MDict(mdx)解析(minilzo)。
  • 工程含义:KindleMate2 做“导入 KMate 数据”可直接读 km3.dat 走 SQL 迁移,主要差异点是 key(32 位 hex)与 source 语义。

4.3 其余表要点

  • original_clipping_lines(id, key, line1…line5):My Clippings 逐行原文;行数 5,991 > clippings 5,988,去重合并时原行被保留到保留条目(需在迁移时验证此规则)。
  • vocab:word 显示词、stem 词干、translation(富文本)与 translation_plain(纯文本)、dict_source(词典来源)、frequency(词频);last_reviewed / review_count / word_level = 闪卡学习状态字段;colorRGB 同标注表。
  • lookups:word_key 带语言前缀(样本 zh:潜龙勿用,英文为 en:…);usage 存原句、title/authors 记录所在书;idx_lookups_unique_norm 提供规范化去重。
  • books:title/author/isbn/language/genre/publication_year + image_data(BLOB 封面)/image_url;是“书目编辑 + 名称映射 + Apple Books 书目”的落点(当前 0 行)。
  • tags_* / pending_deletions:标签与同步删除队列结构已建,待使用。

06与 KindleMate2(KM2 格式)迁移对照

两库同源、列名基本一致,迁移可走 SQL 级搬运;风险点集中标注如下。

km3 表目标(KM2 侧)注意点
clippingsclippingskey(32 hex)与 KM2 主键格式不同:建议保留原 key 到独立列,目标主键重建;brieftype 0/1 枚举需与 KM2 定义核对;source 落新列或前缀;note_parent_key 关系需随迁并重建索引;忽略 read/sync/ck_synced 或置默认
original_clipping_linesoriginal_clipping_lines按 key 关联搬运;行数 > clippings 的现象需在迁移逻辑中容忍(保留行映射)
vocabvocabword_key 语言前缀(zh:/en:)需兼容;translation_plain/dict_source 若 KM2 无对应列可忽略或并入 translation;学习状态列(last_reviewed/review_count/word_level)可直接保留以备将来
lookupslookupsword_key 前缀同上;usage/title 直接搬
books(KM2 无独立书目表)可选:新建书目表,或并入“书名规范/改名”功能复用
tags_* / pending_deletions(无)暂忽略;标签可在 KM2 引入标签后迁移

工程量判断(2026-09-05 本机样本 dry-run 实测):按目标 schema 在内存中逐行回放,clippings 5,988 / lines 5,991 / lookups 175 / vocab 172 全部插入成功、零冲突。要点:

  • 源 key 全部为 32-hex 且库内唯一 → 可直接作为目标主键;clippings 各列数值/时间格式与目标完全兼容(非标准时间 0、colorRGB 空 → -1 转换 0 失败)。
  • vocab:源 INTEGER id 不能直搬,改用 word_key 派生 TEXT id(样本 word_key 全唯一,0 冲突)即可。
  • original_clipping_lines 比 clippings 多 3 条孤儿行(key 已被 KMate 去重清理):迁移时需按 key ∈ clippings 过滤。
  • 需丢弃的字段/表:source / note_parent_key / ck_synced / created_at·updated_at / translation_plain / dict_source / 闪卡三列 / books / tags_* / pending_deletions(目标暂无对应结构)。
  • 总体:属中低工作量的标准 SQLite 只读 → 目标库回放;风险集中在目标应用层去重/类型枚举,而非读取。

07结论与工程建议

  • “读 km3.dat 直接迁”成立:KMate 数据库未加密、无自定义页编码、标准 SQLite,KindleMate2 的 Microsoft.Data.Sqlite 可直接只读打开。
  • 建议实现“导入 KMate 数据库(km3.dat)”入口,与既有 KM2.dat 导入并列,复用去重与事务框架;导入同时记录 source,为将来的“来源分组”铺路。
  • 迁移对账口径:clippings 按 (bookname, content 归一, clippingdate) 与 KM2 既存数据去重;生词按 word_key 归一。
  • 本报告的工程细节版(含全部列清单与索引)见仓库 docs/KMate_数据格式情报.md。
